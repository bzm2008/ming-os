# Ming OS 对抗性审计与商店/桌面统一设计

## 目标

把已确认的网页 V2 预览落实为可安装的 Ming OS 桌面体验：小组件展开不改变胶囊尺寸，应用抽屉从工作区底部向上展开并展示全部已安装入口，桌面右键支持添加到桌面和新建文件；Ming 应用商店使用 Debian AppStream 动态目录，覆盖真实可安装的 Debian 软件，并以受控方式展示国内厂商官方 Linux 软件和 Wine 应用。

## 视觉与交互契约

- 收起胶囊固定为时间、日期、Wi-Fi 图标、可选电池图标/电量、Ming 标志和箭头；展开面板使用独立浮层定位，不参与胶囊布局，因此胶囊宽度和位置不变。
- 展开面板包含 Wi-Fi、蓝牙、亮度、通知、设置、电源、内存/CPU/网速和音量/亮度控制。Win 键、胶囊和 Ming 标志均可切换；收起时资源采样停止或降频。
- 抽屉固定锚定工作区底部，向上展开，Dock 保持独立层级；全屏或抽屉展开时 Dock 下沉/隐藏，不产生底部空白。
- 桌面右键提供“添加到桌面”“新建空白文件”“新建文件夹”“打开应用抽屉”“Ming 设置”“刷新桌面”。文件管理器通过用户模板目录提供同样的新建能力。

## 应用商店架构

商店 UI 只依赖 Provider 接口。Debian Provider 首先读取本地 AppStream 元数据，按包名、架构、候选版本和 desktop ID 生成目录，目录缺失时显示明确的“目录不可用”，不伪造应用。商店可以展示 1000+ 条目，但只有 APT 候选版本经过签名仓库验证并读回 dpkg 状态后才显示安装成功。

国内源选择器管理阿里云、中科大、清华和 Debian 官方备用源。只修改 Ming 标记的源文件；每个候选源必须通过 HTTPS `InRelease` 健康检查和 `apt update`，验证后原子替换，失败恢复备份。厂商官方软件（微信、WPS、QQ、钉钉）和 Wine 软件只有固定版本、amd64/universal 架构、HTTPS 地址及 SHA256 时才允许安装；未满足时显示来源详情而不是安装按钮。

Wine 条目通过独立前缀和 `ming-toolbox`/`ming-launch` 启动，不让商店直接执行 EXE/MSI。每次安装、卸载和启动都读回真实状态并记录脱敏日志。

## 桌面入口清理

核心系统功能先由 Ming 设置、Ming 文件、Ming 终端、网络/音频/蓝牙/电源/时间/输入法页面承接，再将对应可见的 Xfce 原版 desktop 设为 `NoDisplay=true`。保留底层 Xfce 服务和显式兼容入口，禁止删除运行时依赖。桌面、抽屉、Dock 和启动代理使用同一 canonical desktop ID，并按包名、StartupWMClass 和规范 ID 去重。

## OTA 审计边界

OTA 必须从可信 API 获取 schema、签名和版本前进信息；下载、校验、备份、A/B 槽位写入、GRUB 一次性启动、启动健康确认和回滚均为可观察状态。任何签名、版本、UUID、容量、挂载、GRUB 回读或健康确认失败都停止并恢复上一个安全状态。旧域名只作为诊断信息，不作为自动可信回退路径。

## 验收

- 组件：固定胶囊几何、展开零布局变化、Win 键和鼠标切换、资源采样边界、低资源模式。
- 抽屉/右键：底部锚点、全应用目录、添加到桌面、新建空白文件/文件夹、重复进程与全屏层级。
- 商店：AppStream 数量、离线缓存、国内镜像切换、APT 签名、Wine 条目身份、安装/卸载读回、失败状态和日志。
- 桌面：Xfce 可见入口清单、Ming 设置功能覆盖和 canonical desktop 去重。
- OTA：schema/Minisign、严格版本前进、断点/超时、A/B 与非 A/B 路径、GRUB 和回滚故障注入。

源码阶段运行全量 `unittest`、修改 Python 的 `py_compile`、修改 Shell 的 `bash -n` 和 `git diff --check`；真实硬件、ISO 和生产服务另行授权。
